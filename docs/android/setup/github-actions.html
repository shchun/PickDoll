로컬 PC를 점유하지 않고 Android APK·Windows 실행 패키지를 생성합니다.

구성과 현재 상태

GitHub Actions가 Unity Build Automation API에 빌드를 요청하고 상태를 확인합니다. 실제 Unity 실행은 Unity 공식 클라우드에서 수행합니다. Android·Windows를 순차 빌드하고 같은 Git 커밋이 빌드됐는지 확인한 후 파일·SHA256 체크섬을 Actions 산출물로 7일 보관합니다. 릴리즈는 자동 게시하지 않습니다.

2026년 11월 27일: API 인증·프로젝트 조회·두 대상 설정 보정 성공. 파이프라인·알림 테스트 14개·actionlint 구문 검사 통과. 첫 실제 클라우드 요청 접수 완료: Android 빌더 배정·준비 대기. 완료 후 Windows를 순차 요청한다. 결과 회수·서명 검증의 실빌드 확인은 아직 대기 중이다. 첫 시험 실행.

Unity 버전은 저장소의 Unity/ProjectSettings/ProjectVersion.txt에서 감지합니다. 현재 6000.5.5f1입니다. 씬은 커밋된 EditorBuildSettings를 사용하며 CI가 주차별 씬 생성기를 실행하거나 게임 버전을 임의로 올리지 않습니다.

평소 실행 방법

  1. 빌드할 게임 변경을 커밋·푸시합니다.
  2. GitHub 저장소의 Actions → Unity Cloud Build → Run workflow를 엽니다.
  3. 브랜치는 보통 main, operation은 build, platform은 both를 선택합니다. android 또는 windows만 선택할 수도 있습니다.
  4. 실행이 성공하면 해당 실행의 Artifacts에서 결과를 받습니다. Windows ZIP 전체를 풀고 Start-PickDoll.cmd를 실행합니다.

inspect는 읽기 전용 설정 조회이며 빌드를 시작하지 않습니다. configure는 기존 서명·머신 설정을 유지하면서 브랜치 main, 프로젝트 경로 Unity, 버전 자동 감지, 자동 빌드 끄기, 실행 파일 이름 PickDoll을 적용합니다.

자동 빌드·일정 실행은 끄고 마감 때 수동 실행합니다. 워크플로가 중단되거나 시간 초과된 경우 Unity 쪽 빌드가 계속 실행될 수 있으므로, 재실행 전에 Unity Dashboard의 기존 요청을 확인합니다. 클라우드 비용을 유발할 수 있는 빌드 POST는 자동 재시도하지 않습니다.

필요한 자격 정보

GitHub에는 UNITY_BUILD_API_KEY Secret 하나를 등록합니다. Unity 계정 이메일·비밀번호·Personal 라이선스 파일은 GitHub에 등록하지 않습니다.

  1. Unity Cloud에서 조직·프로젝트를 선택하고 Build Automation을 엽니다. 메뉴가 없으면 Development의 Shortcuts 옆 +에서 추가합니다.
  2. Build Automation Settings의 API settings에서 API Key를 생성·복사합니다. 이미 숨겨졌다면 기존 키를 쓰는 연동을 확인한 후 Regenerate합니다.
  3. GitHub Actions Secrets에 UNITY_BUILD_API_KEY로 저장합니다. 값을 소스·로그·채팅에 넣지 않습니다.

동일 이름의 PickDoll 프로젝트가 여러 조직에 있으면 GitHub repository variable UNITY_CLOUD_PROJECT_ID로 대상을 지정합니다. 현재는 이름으로 유일한 프로젝트를 자동 선택합니다.

Unity가 GitHub를 읽는 접근 토큰은 Unity Dashboard에 따로 보관합니다. Fine-grained 토큰을 쓴다면 PickDoll 저장소의 Contents read-only 권한으로 수동 빌드할 수 있습니다. 토큰 만료 시 이 연결도 갱신해야 합니다.

현재 PC는 Personal의 UnityEntitlementLicense.xml 방식입니다. GameCI의 예전 .ulf 파일 복사 안내를 그대로 적용하지 않습니다. 이 워크플로는 GameCI 컨테이너를 실행하지 않습니다.

Android 서명과 기존 기록

현재 테스트 APK와 동일한 디버그 키를 Unity의 PickDoll-test Credentials로 등록했습니다. 인증서 SHA256은 705d4618d4d96e83b4b62f4dc7c3ebfb44c6d9cbfa8b94ebb73f1b67176b5f42입니다. 키 파일은 소스·Actions 산출물에 포함하지 않습니다. 같은 패키지명과 서명으로 기존 앱 위에 설치해야 로컬 수집 기록을 유지할 수 있습니다. 앱 삭제로 기록을 해결하려 하지 않습니다.

스토어 출시용 키와 Play App Signing은 별도 작업입니다. 테스트 키를 바꾸면 기존 디버그 앱과 업데이트 호환성이 달라집니다.

대기·실패와 비용

sentToBuilder는 요청이 빌더로 전달됐지만 컴파일은 아직 시작하지 않은 상태입니다. started 이후 빌드 로그가 표시됩니다. 중복 요청 없이 기존 실행을 기다립니다. 최대 상태 확인 시간은 플랫폼당 90분이며, 시간 초과가 빌드 취소를 뜻하지는 않습니다.

공개 GitHub 저장소의 표준 러너 실행료와 Unity 클라우드 빌드 사용료는 별개입니다. Unity의 무료 사용량·머신별 단가·계정 과금 설정을 기준으로 비용이 계산됩니다. Micro·순차 실행·Library 캐시·수동 실행을 기본으로 합니다. 사용자 선택으로 머신을 바꾸려면 사전 검사 기준과 예산도 함께 검토합니다.

현재 CI는 컴파일·클라우드 결과 회수·패키징 검증을 수행합니다. Windows 플레이어의 기존 집기·배출·도감 통합 검사와 Android 실기기 조작 시험을 대신하지 않습니다.

Slack 완료 알림

사용자가 지정한 incoming webhook은 GitHub Secret SLACK_WEBHOOK_URL에만 저장합니다. 실제 URL은 문서·소스·로그에 넣지 않습니다. 정상 빌드 실행이 완료되면 별도 Unity Cloud Slack Notification 워크플로가 성공·실패·취소와 Actions 결과 링크를 전송합니다. inspect·configure 실행은 완료 알림 대상이 아닙니다.

설정 중 이미 시작한 첫 빌드에는 run ID를 지정한 수동 감시를 연결했습니다. UNITY_SLACK_MANUAL_RUN_ID repository variable로 같은 실행의 자동 알림 중복을 피합니다. 빌드 워크플로 안에서 직접 전송하지 않으므로 빌드 단계 실패 때도 알림을 보낼 수 있습니다.
