  • APK로 초기 배포, Play 테스트·출시에는 AAB 사용

가장 큰 선행 검증: 기존 MuJoCo의 접촉과 집기 감각이 Unity 물리에서 그대로 재현되지는 않는다. 첫 2주에 기본 인형을 집고 운반하는 시제품을 검증한다. 불안정하면 콘텐츠 제작 전에 집게 구조·충돌체·물리 설정을 조정하고 일정을 다시 산정한다.

기존의 조작·상태 전환·음원·미술 방향은 참고하고, 물리와 렌더링 코드는 Unity에 맞춰 새로 구현한다. Unity 프로젝트는 기존 Python·웹 버전과 분리해 PickDoll/Unity/에 생성했다. 2주차는 세 손가락 관절·접촉·마찰로 집고 수동 운반·놓기를 검증했으며, 집게 전체의 수동 회전 제거와 관성 매달림은 3주차 작업이다.

게스트 기록을 기존 클라우드 계정에 연결할 때는 양쪽 기록과 처리 결과를 보여준다. 이미 연결한 게스트 기록을 재연결해 중복 수입하지 않도록 식별자를 보존한다. 다른 Google 계정으로 바꾸면 저장 영역을 분리한다. 세부 병합 규칙은 13주차에 복사·재설치·계정 변경 시험을 통해 확정한다.

제품성 검증을 수익화보다 우선한다. 집는 재미의 가능성은 있지만 현재 상태가 돈을 내고 즐길 만큼 완성됐는지는 아직 모른다. 광고나 결제를 추가하기보다 조작감·인형의 매력·반복해서 할 이유를 먼저 검증한다. 이번 논의는 광고·결제 구현 착수나 유료 출시 확정을 뜻하지 않는다.

시장과 차별화에 대한 판단

Clawbert 같은 수집 중심 게임과 Soft Toys Claw 같은 3D 물리 기반 게임이 이미 있다. 특히 후자는 물리·자유 시점·수집 기능을 안내하므로 물리적으로 움직이는 것만으로 차별화하기는 어렵다고 판단한다. 경쟁작의 누적 다운로드는 유료 구매 수요나 PickDoll의 예상 매출을 증명하지 않는다. 직접 플레이 비교는 별도 검증 과제다.

제품 방향 후보는 조작 실력이 늘수록 성과를 납득할 수 있는 인형뽑기와 갖고 싶은 인형의 수집이다. 광고·코인 대기 없이 편하게 반복 플레이할 수 있다는 점도 차별화 후보지만, 실제 이용자가 가치를 느끼는지는 확인해야 한다.

광고 수익에 대한 현실적인 가정

사용자는 기존 제품에서 액티브 이용자 10명을 넘기기도 어려웠다는 경험을 공유했다. 일간 이용자 1,000명을 기본 전제로 매출을 계획하지 않는다. 다운로드 수보다 실제 활성 이용자·재방문·광고 노출 수가 중요하다.

광고 수익 계산은 하루 실제 노출 수 × 30 ÷ 1,000 × eCPM으로 단순화할 수 있다. 예를 들어 일간 이용자 10명, 1인당 하루 실제 노출 2회, eCPM 3,000원을 모두 가정하면 월 약 1,800원이다. 이는 시장 평균이나 매출 예측이 아닌 계산 예시이며 실제 단가·광고 공급·노출에 따라 달라진다. 소규모에서는 연동·운영 부담과 플레이 흐름 훼손에 비해 수익이 작을 수 있어 광고 도입은 보류한다. AdMob eCPM 설명

나중에 광고를 검토한다면 사용자가 선택하는 보상형을 후보로 둔다. 기본 플레이나 정상적인 집기 성능을 광고 시청에 종속시키지 않고 집기·운반 도중의 광고는 피한다. 현재 일정에는 광고 SDK 구현을 추가하지 않는다.

하강 중에도 수평 이동

집게가 내려가는 동안에도 좌우·앞뒤 조작을 허용한다. 승강과 수평 이동을 동시에 처리하고, 미세 이동과 이동 한계를 유지한다.

완료 확인: 하강 중 입력이 즉시 수평 이동에 반영되며, 입력을 놓으면 멈춘다. 닫힘·상승 중 조작 허용 범위는 구현 시 별도로 정한다.

수동 회전 대신 관성 회전·흔들림

집게의 회전을 직접 제어하지 않는 방식으로 바꾼다. 회전 버튼과 키 입력을 없애고, 이동·가감속에 따라 매달린 집게가 물리적으로 회전하고 흔들리게 한다.

원형으로 반복 이동하면 집게가 원형으로 크게 흔들릴 수 있어야 한다. 정해진 원형 애니메이션을 재생하는 대신, 질량·매달린 길이·관절·감쇠에 따른 결과로 구현한다.

완료 확인: 직선 가감속, 방향 반전, 원형 이동을 비교한다. 원형 입력에 따라 흔들림이 커질 수 있고, 입력을 멈추면 감쇠한다. 유리벽·기구와의 충돌 및 흔들림 한계도 함께 검증한다.

실제 집게를 참고한 디자인 개선

현재 집게가 지나치게 투박하다는 피드백. 인터넷에서 실제 인형뽑기 집게의 형태와 구조를 조사한 뒤, 가는 손가락·곡선형 끝단·중앙 하우징·관절 표현을 개선한다. 기존 물리 집기 성능을 함께 재검증한다.

초기 참고: Smart Industries 제품 자료, SEGA 크레인 게임 안내. 최종 형태는 3주차에 비교 후 결정한다.

구석 인형 집기 개선

벽·모서리에 붙은 인형을 잡기 어렵다는 피드백. 집게 이동 범위, 펼친 손가락의 벽 충돌, 손가락별 관절 반응, 인형과 벽 사이 여유를 확인해 개선한다.

완료 확인: 네 모서리와 네 벽 근처에 놓인 인형으로 접근·하강·닫힘·상승을 시험한다. 벽 충돌은 유지하며, 특정 손가락만 닫히거나 이동 제한 때문에 접근 자체가 불가능한 상황을 개선한다. 모든 시도의 성공을 강제하지 않는다.

3주차에 수동 회전을 관성 회전으로 대체하고 집기 하강 중 이동을 허용했다. 3주차 기능 구현·PC 실행 검사와 폴드5 사용자 정상 동작 확인을 완료했다. 모든 구석·모든 시도의 성공을 뜻하지 않으며, 이후 4주차에서 곡선·접촉·감쇠·속도·그립을 조정하고, 새 정지 조준 조건의 PC 18회 집기·OPEN과 S26 울트라 조작을 확인했다. 18/18은 지정 배치·일반 강도 조건이며 실제 승률이 아니다. 자세한 결과는 각 주차 보고서를 참고한다.
