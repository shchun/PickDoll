01. 목표와 첫 버전 범위

광고나 결제 없이도 반복해서 즐길 수 있는 작은 3D 인형뽑기 게임을 만든다. 목표는 기존 화면을 복제하는 데 그치지 않고, 인형의 모양과 집는 감각이 다른 수집 게임으로 발전시키는 것이다.

항목계획결정 상태
플랫폼·엔진Android / Unity로 새로 제작확정
수익화첫 버전 광고·결제 없음. 유료 에셋 구매 없음확정
핵심 기능뽑기, 누적 획득 업적, 간단한 도감확정
계정·복원비로그인 플레이 가능. Google Play Games 연동 시 업적·클라우드 복원확정
기존 조작 계승기계 정면 기준 이동, 미세 이동, 집게 회전, 자유 시점, 상단 이동 장치 기준 조준원계획에 반영
판 구성한 판에 7개 랜덤 배치, 새 판에서 재배치, 횟수 제한 없음초안
화면·언어세로 화면 우선, 한국어 우선, 폴더블 화면 대응초안
보류 기능랭킹, 일일 미션, 복수 기계, 연체 물리, iOS, 앱 내 실제 경품첫 버전 제외

계획 확정은 구현 완료를 뜻하지 않는다. Unity 버전·Android SDK·플러그인 조합은 첫 주에 호환성을 확인해 고정한다. 공개 출시일은 아직 정하지 않았다.

02. 인형은 색보다 형태를 다양하게

단순한 얼굴 교체보다 실루엣 차이를 우선한다. 아래 12종은 제작 후보이며, 3종 시제품으로 집기와 작업량을 확인한 뒤 최종 구성한다.

동물 후보 6종

토끼 · 곰 · 고양이 · 펭귄 · 물개 · 가오리

긴 귀와 몸통, 둥근 몸체, 짧은 팔다리, 길쭉한 몸, 납작한 날개 등으로 구분한다.

음식·사물 후보 6종

딸기 · 도넛 · 식빵 · 푸딩 · 별 · 쿠션

원뿔형, 고리형, 납작한 사각형, 둥근 밑면, 돌출부가 있는 형태를 조합한다.

  • 자체 캐릭터로 제작하며 유명 캐릭터의 외형은 사용하지 않는다.
  • 형태에 맞는 단순 충돌체와 질량 배분을 설계한다. 모든 인형에 동일한 무게중심을 적용하지 않는다.
  • 난이도는 외형·무게중심·마찰·크기의 조합으로 조정한다. 특정 종류가 사실상 획득 불가능해지지 않게 시험한다.
  • 푹신함은 천 재질, 둥근 모델, 가벼운 눌림·복원 연출로 표현한다. 실제 접촉은 강체 물리로 시작한다.
  • 도넛처럼 구멍이 있는 인형은 단일 볼록 충돌체로 구멍을 막지 않도록 여러 충돌체로 구성한다.

03. Unity 기술 설계

게임과 물리

  • Unity + URP 기반 모바일 3D 렌더링
  • Rigidbody·Collider·Joint로 집게와 인형 구현
  • 이동 → 하강 → 닫기 → 상승 → 복귀 → 배출 상태 분리
  • 관성 흔들림과 약한 그립을 조절 가능한 설정으로 관리
  • 조준원은 상단 이동 장치의 수직 아래 표시

콘텐츠와 앱 기능

  • 인형 ID·표시 이름·물리 설정·모델을 데이터로 분리
  • 게임 상태와 UI, 저장·서비스 연동을 분리
  • 로컬 저장은 버전 필드와 원자적 파일 교체·백업 적용
  • Google Play Games 공식 Unity 플러그인 연동
  • APK로 초기 배포, Play 테스트·출시에는 AAB 사용

가장 큰 선행 검증: 기존 MuJoCo의 접촉과 집기 감각이 Unity 물리에서 그대로 재현되지는 않는다. 첫 2주에 기본 인형을 집고 운반하는 시제품을 검증한다. 불안정하면 콘텐츠 제작 전에 집게 구조·충돌체·물리 설정을 조정하고 일정을 다시 산정한다.

기존의 조작·상태 전환·음원·미술 방향은 참고하고, 물리와 렌더링 코드는 Unity에 맞춰 새로 구현한다. 새 프로젝트는 기존 Python·웹 버전과 분리해 PickDoll/Unity/에 두는 안을 기본으로 한다. 이번 문서 작성에서는 Unity 프로젝트를 생성하지 않는다.

04. 수집·업적·도감·클라우드 저장

  1. 배출 완료 확인
  2. 획득 이벤트 1회 기록
  3. 로컬 저장
  4. 도감 갱신
  5. 로그인 상태에서 동기화·업적 반영
업적 후보조건판정
첫 친구누적 1개여러 판에 걸친 성공 획득 합계.
동일 종류를 반복 획득해도 증가.
올려 잡은 것만으로는 증가하지 않음.
작은 수집가누적 10개
수집의 시작누적 20개
뽑기의 달인누적 50개
인형 백화점누적 100개
수집 전문가누적 200개

10·20·50개 기준은 사용자 확정. 1·100·200개와 업적 이름은 제안이며, 업적 ID·아이콘은 구현 시 등록한다.

획득과 도감

  • 배출 경로를 거쳐 최종 배출 확인 지점에 도달하면 획득
  • 배출 감지의 중복 콜백·앱 재실행으로 같은 인형을 재집계하지 않음
  • 도감은 미획득 실루엣, 이름, 획득 수, 모델 회전 미리보기 제공
  • 새 판은 현재 인형만 초기화하고 누적 기록은 유지
  • 중단된 판은 첫 버전에서 재구성하며, 완료된 획득 기록을 보존

로그인과 동기화

  • 인증 실패·취소·오프라인이어도 게임 진행 가능
  • 기기 내 게스트 기록은 자동 저장. 클라우드 반영 전 삭제·분실 시 복원 보장 불가
  • Google 연동 후 Saved Games에 누적·종류별 기록 저장
  • 업적 상태 자체를 수집 기록의 원본으로 사용하지 않음
  • 오프라인 업적은 기록에서 재계산해 연동 후 반영
두 기기 사용과 기록 충돌 처리

S26 울트라와 폴드5가 같은 기록을 내려받은 뒤 각각 플레이해도 기존 획득을 두 번 더하면 안 된다. 제안 설계는 저장 계정에 속한 각 설치의 기여 카운터를 종류별로 관리하고, 같은 설치 항목은 최댓값으로 병합한 뒤 합계를 계산하는 방식이다. 새 설치에는 새 ID를 부여하고 스키마 버전을 저장한다.

게스트 기록을 기존 클라우드 계정에 연결할 때는 양쪽 기록과 처리 결과를 보여준다. 이미 연결한 게스트 기록을 재연결해 중복 수입하지 않도록 식별자를 보존한다. 다른 Google 계정으로 바꾸면 저장 영역을 분리한다. 세부 병합 규칙은 9주차에 복사·재설치·계정 변경 시험을 통해 확정한다.

05. 주당 6시간 제작 일정

매주 구현 4시간 + 실기기 검증·수정 1시간 + 기록·다음 작업 준비 1시간을 기본으로 한다. 아래 기간은 추정이며, 특히 인형 모델 제작과 물리 튜닝에 따라 변동한다.

3주착수 전 리마인드: 하강 중 이동, 수동 회전 제거와 관성 회전·원형 흔들림, 집게 디자인 개선, 구석 인형 집기 개선을 함께 검토·적용.

06. 실기기 시험과 출시 조건

게임·기기

  • S26 울트라·폴드5에서 60fps 목표. 실측 후 품질 단계 조정
  • 폴드5 외부·내부 화면과 실행 중 접기·펼치기 대응
  • 인형별 집기·탈락·구석·유리벽·배출구 끼임 검증
  • 가속할 때 집게는 흔들리고 조준원은 안정적으로 표시
  • 앱 전환·화면 잠금·종료·재실행 후 조작 복구
  • 장시간 플레이 중 발열과 프레임 저하 확인

기록·서비스

  • 9→10, 19→20, 49→50 경계에서 업적 판정
  • 중복 배출 감지·재시도에서도 획득 수 유지
  • 비로그인 플레이 후 로그인·오프라인 후 재연결
  • 두 기기 동시 진행·순서가 뒤바뀐 저장 병합
  • 클라우드 저장 후 재설치해 복원
  • 계정 변경 시 다른 사람의 기록과 섞이지 않음

오래된 개인 개발자 계정을 보유하고 있으므로 신규 개인 계정용 테스트 요건은 원칙적으로 대상이 아닌 것으로 계획한다. 실제 계정의 제작 액세스·정책 상태는 Play Console에서 확인한다. 신규 개인 계정의 12명·14일 요건과 별개로 지인 테스트와 Play 내부 테스트는 진행한다.

출시 전 패키지명·앱 이름·서명 키 보관, Play App Signing·테스트/출시 인증서 설정, 대상 API 및 Android 호환 요구사항, 콘텐츠 등급·타깃 연령·데이터 보안·개인정보처리방침·에셋 권리·Play Games 리소스 공개 상태를 확인한다. 출시 시점의 정책을 다시 점검한다.

추가 피드백 · 향후 조작·관성 과제

2026년 11월 21일 사용자 피드백. 이번 2주차의 기본 집기 구현과 구분해 후속 과제로 관리한다. 사용자가 3주차 작업을 요청하면 구현 착수 전에 이 대화에서 아래 네 항목을 다시 짚고 적용한다. 집게 디자인과 구석 집기 개선도 사용자 요청에 따라 3주차에 진행하며, 2주차에는 적용하지 않는다.

하강 중에도 수평 이동

집게가 내려가는 동안에도 좌우·앞뒤 조작을 허용한다. 승강과 수평 이동을 동시에 처리하고, 미세 이동과 이동 한계를 유지한다.

완료 확인: 하강 중 입력이 즉시 수평 이동에 반영되며, 입력을 놓으면 멈춘다. 닫힘·상승 중 조작 허용 범위는 구현 시 별도로 정한다.

수동 회전 대신 관성 회전·흔들림

집게의 회전을 직접 제어하지 않는 방식으로 바꾼다. 회전 버튼과 키 입력을 없애고, 이동·가감속에 따라 매달린 집게가 물리적으로 회전하고 흔들리게 한다.

원형으로 반복 이동하면 집게가 원형으로 크게 흔들릴 수 있어야 한다. 정해진 원형 애니메이션을 재생하는 대신, 질량·매달린 길이·관절·감쇠에 따른 결과로 구현한다.

완료 확인: 직선 가감속, 방향 반전, 원형 이동을 비교한다. 원형 입력에 따라 흔들림이 커질 수 있고, 입력을 멈추면 감쇠한다. 유리벽·기구와의 충돌 및 흔들림 한계도 함께 검증한다.

실제 집게를 참고한 디자인 개선

현재 집게가 지나치게 투박하다는 피드백. 인터넷에서 실제 인형뽑기 집게의 형태와 구조를 조사한 뒤, 가는 손가락·곡선형 끝단·중앙 하우징·관절 표현을 개선한다. 기존 물리 집기 성능을 함께 재검증한다.

초기 참고: Smart Industries 제품 자료, SEGA 크레인 게임 안내. 최종 형태는 3주차에 비교 후 결정한다.

구석 인형 집기 개선

벽·모서리에 붙은 인형을 잡기 어렵다는 피드백. 집게 이동 범위, 펼친 손가락의 벽 충돌, 손가락별 관절 반응, 인형과 벽 사이 여유를 확인해 개선한다.

완료 확인: 네 모서리와 네 벽 근처에 놓인 인형으로 접근·하강·닫힘·상승을 시험한다. 벽 충돌은 유지하며, 특정 손가락만 닫히거나 이동 제한 때문에 접근 자체가 불가능한 상황을 개선한다. 모든 시도의 성공을 강제하지 않는다.

현재 프로토타입의 수동 회전과 자동 집기 중 이동 제한은 이 후속 작업에서 변경할 대상이다. 피드백을 기록한 것으로, 이미 구현됐다는 의미는 아니다.
